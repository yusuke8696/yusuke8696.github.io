llama-serverのコンテキスト長とは？
-c・-nを初心者向けに解説

モデルは長いコンテキストに対応しているのに、なぜContext Window Exceededになるのか。llama-server側の設定との違いから整理します。

コンテキスト長とは？

LLMが1回の処理で参照できる情報量には上限があります。大まかには、システムプロンプト、ユーザー入力、会話履歴、ツールから渡された情報、生成に使う領域などが関係します。

そのため、ユーザーの質問が短くても、AIエージェントやコーディングツールから大量の情報が追加されれば、リクエスト全体は大きくなることがあります。

-cはコンテキストサイズ

llama-serverの-c（--ctx-size）は、実行時に利用するコンテキストサイズを指定する設定です。

llama-server -m model.gguf -c 16384
重要：モデルが対応する最大コンテキスト長と、llama-serverで実際に使用するコンテキストサイズは同じとは限りません。

-nとの違い

設定主な役割
-cコンテキストとして扱う領域
-n生成するトークン数の上限に関係する設定
llama-server -m model.gguf -c 16384 -n 2048

長い入力を扱いたい場合に、単純に-nを増やせばよいわけではありません。入力や会話履歴を含む情報量を考える場合は、まずコンテキスト側を確認します。

Context Window Exceededが起きる理由

代表的な原因は、送信しようとしている情報量が実際に利用できるコンテキストサイズを超えることです。

モデルが対応するコンテキスト
        ↓
llama-serverの設定
        ↓
APIクライアント側の設定
        ↓
実際に送信されるプロンプト

モデルの公称スペックだけでなく、この複数の層を確認する必要があります。

AIコーディングツールでは入力が増えやすい

AIコーディングツールでは、質問以外にシステムプロンプト、プロジェクト情報、ファイル内容、会話履歴、ツール定義、ツール実行結果などが追加されることがあります。そのため、画面上では短い質問でもLLMへ送る情報量は大きくなる可能性があります。

-cは大きいほど良い？

必ずしもそうではありません。大きなコンテキストを利用する場合は実行環境側のリソースも考慮する必要があります。モデルの最大値を常に設定するのではなく、短いチャット中心か、大量のコードや文書を扱う用途かなどに合わせて決めます。

まとめ

-cはllama-serverで使用するコンテキスト、-nは生成するトークン数に関係する設定です。Context Window Exceededが発生したら、モデルの仕様だけでなく、llama-server、クライアント、実際のリクエスト量を順に確認すると原因を切り分けやすくなります。

llama-server自体の導入方法は、Qwen系ローカルLLMをllama.cppで動かすも参考にしてください。
