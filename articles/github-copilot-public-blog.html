GitHub Copilotで公開ブログ記事を安全に作る設定

GitHub PagesのPublicリポジトリでブログを運営するとき、VS CodeのGitHub Copilotに記事作成を任せるための指示ファイルと公開前チェックを整理します。

Publicリポジトリでは「すべて公開」が前提

GitHub Pagesで公開するブログは、HTMLや画像だけでなく、Publicリポジトリに入れたファイルとコミット履歴も閲覧できる前提で扱います。記事作成をAIに任せる場合も、公開してよい内容だけを作らせるルールが必要です。

入れてはいけないもの
APIキー、パスワード、アクセストークン、ASPのログイン情報、秘密のURL、個人の住所・電話番号・非公開メールアドレスは、記事にも設定ファイルにも書きません。

リポジトリ全体へ共通ルールを置く

VS CodeのGitHub Copilotでは、リポジトリ直下の .github/copilot-instructions.md に書いた内容を、リポジトリ全体の指示として使えます。記事作成のたびに同じ注意を書かなくてよいのが利点です。

# Public GitHub Pages blog instructions

- Treat every file and its Git history as publicly visible.
- Never create or commit API keys, passwords, tokens, or personal data.
- Do not invent affiliate links, prices, reviews, earnings, or testimonials.
- Add a clear disclosure when an article contains affiliate links.
- Flag time-sensitive claims for review when they cannot be verified from an official source.

指示は長い規約集にするより、AIの判断を変える短いルールに絞ると使いやすくなります。Copilotの回答に指示ファイルが参照として表示されれば、読み込まれていることを確認できます。

記事作成用と公開前確認用を分ける

すべての会話に適用したい内容は共通指示に置き、手順がある作業はskillとして分けると管理しやすくなります。

記事作成skill読者、目的、根拠、広告表記を確認し、オリジナルの下書きを作ります。
公開前レビューskill秘密情報、個人情報、広告表示、リンク、根拠不足、著作権上の懸念を確認します。
共通指示Publicリポジトリで常に守る安全ルールを適用します。
Pull Requestレビュー結果と記事の差分を見てから、自分でマージします。

GitHub CopilotのAgent skillsは .github/skills/skill-name/SKILL.md に置けます。作成とレビューを分けると、公開前に「記事を書くモード」のまま見落とすリスクを減らせます。

アフィリエイト記事で確認すること

  • アフィリエイトリンクがある記事には、読者が見つけやすい位置に広告利用を明記する。
  • 実際に使っていない商品を「使った」と書かない。口コミ、収益、ランキング、比較結果を作らない。
  • 価格、在庫、キャンペーン、仕様、法律など変わりやすい情報は、公開前に公式情報で確認する。
  • 他サイトの商品説明、レビュー、画像、表をそのまま転載しない。引用する場合は必要最小限にして出典を示す。
  • 「必ず稼げる」など、成果を保証する表現は使わない。

広告表示は、サイトの一部だけでなく、読者が広告であることを明確に理解できるかという観点で考える必要があります。最新の考え方は消費者庁のステルスマーケティングQ&Aで確認できます。

公開前の短いチェックリスト

公開する前に、次を確認します。
  • 秘密情報や個人情報を含まないか
  • 広告表記が必要な記事に表示があるか
  • 事実・リンク・価格などの根拠を確認したか
  • 画像や文章を無断転載していないか
  • 収益・効果・順位を断定していないか

AIの出力は下書きとして扱い、PRで最終確認してから公開する運用が現実的です。特に未確認の情報は、削除するか「要確認」として自分で裏付けを取ります。

まとめ

GitHub Copilotは、記事の構成づくりや下書き作成を速くできます。ただし、Publicリポジトリでは秘密情報を守り、広告表示・事実確認・著作権を人が最終確認することが欠かせません。

.github/copilot-instructions.md に共通ルールを置き、記事作成と公開前レビューを別skillにすることで、AIを使う記事更新を継続しやすくなります。
