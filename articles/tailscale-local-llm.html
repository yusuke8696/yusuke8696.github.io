TailscaleでローカルLLMへ外出先からアクセスする方法

自宅PCの llama-server をlocalhostのまま動かし、スマートフォン、ノートPC、GitHub Actionsからtailnet経由で利用する方法を整理します。

構成と前提

Windows PCで動く llama-server のHTTP APIを、同じtailnetに参加した端末から使います。Tailscale Serveがtailnet内のHTTPS URLへのリクエストを、PC内の 127.0.0.1:8080 に転送します。

スマートフォン / ノートPC / GitHub Actions
             ↓ tailnet内のHTTPS URL
       Tailscale Serve（自宅PC）
             ↓ http://127.0.0.1:8080
           llama-server

自宅PCの電源とネットワーク接続、Tailscale、llama-serverが使える状態であることが必要です。Tailscale Serveはtailnet内向けで、公開インターネットから誰でも接続できる設定にはなりません。

1. Windows PCと利用端末をtailnetへ参加させる

Tailscale公式サイトからWindows PCとスマートフォン、またはノートPCにアプリを導入し、同じtailnetへ参加させます。接続可能な相手はtailnetのアクセス制御設定にも従います。

ServeでHTTPSのURLを使うには、tailnetでHTTPS証明書を有効にします。未設定の場合、ServeのCLIから表示される案内に従って設定できます。

2. llama-serverをlocalhostで起動する

モデルの指定は利用環境に合わせ、WindowsのPowerShellで例えば次のように起動します。

llama-server -hf <モデルの指定> --host 127.0.0.1 --port 8080

まず同じPCで http://127.0.0.1:8080/v1/models を開き、サーバーが応答することを確認します。--host 127.0.0.1 のままなら、llama-server自体をLAN全体へ公開せずに済みます。

3. Tailscale Serveで共有する

Windows PCで別のターミナルを開き、次を実行します。

tailscale serve 8080

表示された https://<端末名>.<tailnet名>.ts.net 形式のURLを控えます。このコマンドは通常フォアグラウンドで動くため、ターミナルを閉じたり Ctrl+C を押したりすると共有が止まります。

同じtailnetへ参加したスマートフォンやノートPCから、表示されたURLに /v1/models を付けてアクセスします。

https://<表示されたホスト名>/v1/models
接続できない場合
両端末が同じtailnetに参加しているか、Windows PC上のllama-serverが起動しているか、HTTPS証明書とtailnetのアクセス制御が適切かを順に確認します。

ServeとFunnelの違い

Serve はtailnet内の端末向け、Funnel は公開インターネット向けの機能です。自分の端末や接続を許可したGitHub Actionsから使う用途ならServeを選びます。LLM APIには別途の認証を設けていない場合もあるため、tailnetの参加端末とアクセスルールを管理してください。

GitHub Actionsから利用する場合

Tailscale公式GitHub Actionをworkflowへ追加すると、runnerが一時的なtailnetノードとして参加し、後続のステップから自宅PCのServe URLにアクセスできます。例えば記事生成の推論処理だけを自宅PCのGPUで実行できます。

  1. Tailscale側にCI用のタグと認証設定を作成します。公式手順ではWorkload Identity Federationを推奨しています。
  2. GitHub側には必要な値をSecretsで登録し、workflowで tailscale/github-action@v4 を実行します。連携方式に応じた設定を公式手順で確認してください。
  3. 後続のステップで、ServeのURLに /v1/models を付けて疎通を確認します。CI用タグから自宅PCへの接続をTailscaleのアクセス制御で許可します。
運用上の注意
Workload Identity Federationにはworkflowの id-token: write 権限が必要です。認証情報をworkflowファイルへ直接記載せず、外部から送られる未信頼のプロンプトやPRからこの接続を使わせる場合は、workflowの起動条件と権限も確認してください。自宅PCが停止中ならrunnerからのAPI呼び出しは失敗します。

まとめ

llama-serverを 127.0.0.1:8080 で起動し、tailscale serve 8080 でtailnet内へ共有すれば、外出先の端末からローカルLLMを利用できます。GitHub Actionsも公式Actionでtailnetに参加させる構成が可能です。
