Qwen系ローカルLLMをllama.cppで動かす

Qwen系モデルをGGUF量子化版で入手し、llama.cppのllama-serverから OpenAI互換APIとして利用する方法をWindows環境向けに紹介します。

基本構成

Qwen系モデルをローカルで動かすときは、モデル本体をそのまま実行するのではなく、 GGUF形式の量子化モデルと、それを読み込めるランタイムを組み合わせます。 llama.cppにはHTTPサーバー機能もあるため、対応クライアントから接続できます。

Q4_K_Mとは

Q4_K_Mは、GGUFで利用される量子化方式の一つです。FP16などの高精度な形式と比べて モデルサイズとメモリ使用量を抑えられる一方、量子化による品質低下とのトレードオフがあります。

量子化版はGPUに合わせて選びます。
モデルのファイルサイズだけでなく、推論時のKVキャッシュやコンテキスト長でもVRAM使用量は変わります。 Q4_K_Mでも、GPUのVRAM容量に対して必ず余裕があるとは限りません。

Qwen系モデルの選び方

モデル名やパラメータ数だけで決めず、自分の用途とPCの制約を照らし合わせます。 同じQwen系でも、コーディング、会話、推論、画像入力などで向いているモデルは異なります。

モデルサイズ・パラメータ数メモリ容量と回答品質、速度のバランスを確認します。
量子化方式Q4_K_Mなど、VRAMに収まる形式を選びます。
コンテキスト長長文や大きなソースコードを扱う場合に確認します。
推論速度実際のGPU、CPU、ビルドによる差を考慮します。
Thinking対応回答前の推論過程を使うモデルか確認します。
Tool / Function CallingAI Agentや外部ツール連携の要件を確認します。
Vision対応画像入力が必要な場合は対応モデルを選びます。
ライセンス利用目的と再配布条件をモデルカードで確認します。

広告：この記事にはアフィリエイト広告を含みます。ローカルLLM用のPCを選ぶときは、使いたいモデル、GPUのVRAM、メモリ容量を確認してください。

Qwythos-9B-v2を使う

今回の環境では、Qwen3.5系をベースとした Qwythos-9B-v2-GGUF を利用します。 9BクラスのモデルをQ4_K_Mに量子化した構成で、ローカルGPUのVRAMと品質のバランスを取りやすい選択肢です。

モデルカードでは、標準的なQwen3.5 chat templateを使用すると説明されています。 現代的なGGUFランタイムではテンプレートを自動的に読み込める場合がありますが、 期待どおりに会話できないときはモデルカードとサーバーログを確認してください。 詳しくはQwythos-9B-v2のモデルカードを参照してください。

llama-serverで起動する

llama.cppをインストールした環境では、Hugging Faceのモデル名を指定してサーバーを起動できます。 Qwythos-9B-v2-GGUFのQ4_K_Mを使う場合の例は次のとおりです。 

llama-server -hf empero-ai/Qwythos-9B-v2-GGUF:Q4_K_M \
  --host 127.0.0.1 \
  --port 8080 \
  -ngl 99 \
  -c 16384 \
  -n 8192 \
  --jinja \
  -fa on \
  --alias qwythos-9B-v2

現在のllama.cppでは、次の新しいCLI形式も案内されています。インストールしたバージョンのREADMEに合わせて使い分けてください。 

llama serve -hf empero-ai/Qwythos-9B-v2-GGUF
  • -hf はHugging Face上のモデルを指定し、必要なファイルを取得します。
  • --host 127.0.0.1 --port 8080 はローカルPCの8080番ポートで待ち受けます。
  • -ngl 99 は、可能な範囲でモデルのレイヤーをGPUへオフロードします。
  • -c 16384 はコンテキスト長、-n 8192 は最大生成トークン数の例です。
  • --jinja はチャットテンプレートを使い、-fa on はFlash Attentionを有効にします。
  • --alias はAPI上で表示するモデル名を固定します。
Windowsではコマンドの書式に注意してください。
PowerShellやコマンドプロンプトで行末の \ が継続記号として扱われない場合は、引数を1行にまとめて入力してください。 また、初回起動時はモデルのダウンロードが行われます。

Windowsでの構成と自動起動

Windowsでは、llama.cppのフォルダーに llama-server.exe を置き、 モデルのキャッシュ先や実行ファイルの場所を管理します。サーバーが起動すると、同じPC上のクライアントは次のURLから接続できます。 

Windows
 ├─ llama.cpp
 ├─ llama-server.exe
 │
 └─ Qwen / Qwythos GGUF
        ↓
   http://127.0.0.1:8080

PC起動時に自動で立ち上げたい場合は、Windowsタスクスケジューラーにタスクを登録します。 「操作」のプログラムに llama-server.exe のフルパスを指定し、引数には次のような値を設定します。 

-hf empero-ai/Qwythos-9B-v2-GGUF:Q4_K_M --host 127.0.0.1 --port 8080 -ngl 99 -c 16384 -n 8192 --jinja --alias qwythos-9B-v2

作業フォルダーもllama.cppの配置先に合わせて設定すると、相対パスを使う構成で迷いにくくなります。 タスク登録後は、手動で実行してサーバーが起動することと、ポート8080が待ち受け状態になることを確認してください。

起動できないときの確認ポイント

  • CUDA対応ビルドとNVIDIAドライバーが環境に合っているか確認します。
  • モデルの量子化方式とVRAM容量を確認し、必要ならコンテキスト長を下げます。
  • ポート8080が別のアプリケーションに使用されていないか確認します。
  • チャットの形式が不自然な場合は、モデルのchat templateと --jinja の設定を確認します。
  • サーバーログでモデルの読み込み、GPUオフロード、エラー内容を確認します。

まとめ

Qwen系モデルは、対応するGGUF版を選び、llama.cppの llama-server から起動すると、 OpenAI互換APIとして利用できます。Q4_K_Mのような量子化版を使えば、ローカルGPUでもモデルサイズを抑えて試せます。

最初は小さめのコンテキスト長で動作を確認し、ログとVRAM使用量を見ながら設定を調整するのが現実的です。 利用前には、モデルカードのライセンス、対応機能、推奨テンプレートも確認してください。
