RTX 2060でローカルLLM＋AI Agent環境を構築

VRAM 6GBのRTX 2060で9Bクラスの量子化モデルを動かし、 VS CodeとClineからローカルLLMを使う環境を作りました。

今回作った環境

今回は、インターネット上のLLM APIを呼び出すのではなく、 自分のPC上で推論したモデルをOpenAI互換APIとして公開します。 ClineはそのAPIへ接続し、VS Code上でコードの読み取りや編集を行います。

APIサーバーは 127.0.0.1 にバインドしています。 そのため、同じPC上のアプリケーションから利用でき、外部ネットワークから直接アクセスされる構成にはなりません。 ソースコードやプロジェクトファイルを外部のLLM APIへ送らずに作業できる点が、この構成の大きなメリットです。

Qwythos-9B-v2について

Qwythos-9B-v2は、Qwen3.5系をベースにした9Bモデルです。 GGUF版が公開されているため、llama.cppで扱えます。今回選んだQ4_K_Mは、 モデルのサイズと品質、RTX 2060のVRAM容量のバランスを考えた量子化版です。

reasoningモデルとして、回答前にthinkingを行う形式になっています。 v2では繰り返しやループ挙動の改善を目的としたFTPOが行われています。 モデルカードにはApache-2.0ライセンスが記載されており、利用時は配布元のライセンスとモデルカードを確認してください。

推奨設定として、temperature 0.6、top-p 0.95、top-k 20などが案内されています。 実際の応答は、プロンプト、コンテキスト長、GPUオフロード、llama.cppのバージョンによって変わります。 詳細はHugging Faceのモデルカードを参照してください。

llama-serverの起動設定

llama.cppに含まれる llama-server は、ブラウザやクライアントからHTTPで呼び出せる推論サーバーです。 OpenAI互換の /v1/chat/completions などのエンドポイントを提供するため、対応クライアントから接続できます。 

llama-server \
  -hf empero-ai/Qwythos-9B-v2-GGUF:Q4_K_M \
  --host 127.0.0.1 \
  --port 8080 \
  -ngl 99 \
  -c 16384 \
  -n 8192 \
  --jinja \
  -fa on \
  --verbose \
  --alias qwythos-9B-v2

Windowsの環境によっては、行末の \ を使わず、1行で入力してください。

  • -hf はHugging Face上のモデルを指定します。
  • --host 127.0.0.1 --port 8080 はローカルPCの8080番ポートで待ち受けます。
  • -ngl 99 は、可能な範囲でモデルをGPUへオフロードします。
  • -c 16384 はコンテキストサイズ16,384、-n 8192 は最大生成トークン数8,192です。
  • --jinja はモデルのチャットテンプレートを利用し、-fa on はFlash Attentionを有効にします。
  • --verbose でログを詳しく表示し、--alias でAPI上のモデル名を固定します。
設定値は固定の正解ではありません。
16,384トークンのコンテキストを確保すると、モデル本体以外にもKVキャッシュ用のメモリが必要になります。 VRAM不足や速度低下が起きる場合は、まずコンテキスト長を下げる、またはGPUオフロード量を調整してください。

llama.cppの詳細は公式リポジトリで確認できます。 CUDA対応ビルド、NVIDIAドライバー、モデルのチャットテンプレートの相性によって挙動が変わるため、ログを確認しながら設定を詰めるのが安全です。

Clineから接続する

ClineのプロバイダーでOpenAI Compatibleを選び、llama-serverの接続先を指定します。 表示名や項目名はClineのバージョンで変わる場合がありますが、基本的には次の値を使います。 

Provider: OpenAI Compatible
Base URL: http://127.0.0.1:8080/v1
Model ID: qwythos-9B-v2
API Key: （ローカルサーバーが要求する場合のみ設定）

接続後は、ClineがVS Codeのワークスペースを読み取り、必要に応じてファイル編集やコマンド実行を提案します。 実行前に差分とコマンドを確認し、プロジェクトのバックアップやGit管理も併用すると安心です。 Clineの設定についてはOpenAI Compatibleの公式ドキュメントを参照してください。

RTX 2060 6GBで使うときのポイント

RTX 2060でも、Q4_K_Mの9Bモデルをローカルで動かせます。ただし、モデルサイズだけでなく、コンテキスト長やKVキャッシュ、GPUに載せるレイヤー数もVRAM使用量に影響します。 「9Bなら必ず余裕」という意味ではありません。

  • 大規模モデルほどVRAMに収まりにくく、CPUとの間でデータを移動する場面が増えます。
  • 長いコンテキストや大きなファイルを渡すと、メモリ使用量と応答時間が増えます。
  • 速度やVRAM使用量は、PC環境、ドライバー、llama.cppのビルド、モデル、設定で変化します。

実測するときは、サーバーのログとタスクマネージャー、またはNVIDIAの nvidia-smi を同時に確認します。 記録する項目は、モデル読み込み後のVRAM使用量、生成中の速度（tokens per second）、コンテキスト長、設定値です。 環境が違う読者でも再現しやすいように、測定時の条件を添えて記録するのがおすすめです。

広告：この記事にはアフィリエイト広告を含みます。GPU搭載PCを検討するときは、用途に必要なGPU、VRAM、メモリ容量を確認してください。

測定時は、同じプロンプトと同じコンテキストで、ロード開始から応答可能になるまでの時間、nvidia-smi のVRAM、タスクマネージャーのメモリ、サーバーログの生成速度を記録します。 Clineでは、短い関数の修正、複数ファイルの変更、長いログの要約を分けて試すと、どこまで実用になるかを判断しやすくなります。

現時点での判断基準
16,384 contextは長いコードベースを一度に扱うための設定ですが、VRAMと速度の余裕を保証するものではありません。 まず短いコード修正でツール操作が安定するかを確認し、長い入力や複数ファイルの編集は実測後に範囲を広げます。

まとめ

llama.cppの llama-server を使えば、RTX 2060 6GBでも9Bクラスの量子化モデルをOpenAI互換APIとして公開できます。 ClineとVS Codeを組み合わせることで、有料APIを使わずにローカルAI Agentによるコーディング環境を構築できました。

月額API費用を抑えられ、ソースコードを外部サービスへ送らない構成にできる一方、GPUメモリの制約はあります。 まずは小さめのコンテキストと短いタスクから試し、ログとVRAM使用量を見ながら自分のPCに合う設定を探すのが現実的です。
